# Axoniq Docs Restyle — Engineering Notes

State of the restyle for handoff. It spans two repos:
- **`axoniq-library-ui`** (this repo) — the Antora UI bundle: partials, CSS, JS.
- **`axoniq-library-site`** — the Antora playbook + the `nav-assembler` extension and
  `nav-manifest.js` that drive the dynamic navigation (see NAV-PLAN.md).

Build artifacts (`build/`, `node_modules/`, `public/`) are git-ignored. Content comes
from the ~18 source repos via the site playbook, not from here.

---

## 1. Navigation drawer — now DYNAMIC (was hardcoded)

Previously the drawer was hand-authored static markup. It is now assembled from
**Antora's own navigation model**:

- `src/partials/nav-drawer.hbs` authors only the **header** (brand + product/version
  switcher) and **footer** (Axoniq Platform + theme toggle). The tree itself is
  `{{> nav-generated}}`.
- `src/partials/nav-generated.hbs` is a **stub**. At site-build time the
  `nav-assembler` Antora extension (in `axoniq-library-site/lib/nav-assembler.js`)
  **overrides it** with the real navigation, assembled from `nav-manifest.js` (the
  curated fixed sections) + each component's `nav.adoc`.
- The generated markup uses the same classes/attributes as before
  (`nav-section`, `nav-tree`, `details.nav-group`, `nav-link[data-href]`), so the
  existing `app.js` behaviour — active-path highlighting, ancestor auto-expand,
  collapse persistence — works unchanged. Verified: on a deep page the correct link
  gets `is-current` and its ancestor groups open.

**Result:** adding a page to a repo's `nav.adoc` makes it appear in the drawer on the
next build — no theme edit. Full rationale, ownership split, and rollout in NAV-PLAN.md.

### ⚠️ One prerequisite engineering must know
A component only contributes nav if it **declares `nav:` in its `antora.yml`**. The
Axon Framework reference (`axon-framework-reference`) did **not** — its nav lives in
`modules/ROOT/partials/nav.adoc` but was never declared, so Antora built *zero*
navigation for it. **That is the real reason the drawer was hardcoded.** The fix is one
line in that component's `antora.yml`:

```yaml
nav:
  - modules/ROOT/partials/nav.adoc
```

Once declared, Core concepts / Operations / Migration / Release notes populate
automatically (verified: 27 / 19 / 19 / 4 links). This one-line change must land in the
source repo(s) for production; for the local preview it is applied to the `localLinks`
clone.

### Known refinement
The `home` component's `nav.adoc` is a broad landing nav, so "Getting started" currently
pulls in more than ideal (the whole Reference-Guides submenu). Tighten via manifest
matchers (`urlContains`) or trim `home`'s nav. Tracked in NAV-PLAN.md.

## 2. Search (⌘K) — now WIRED to Lunr (was a mock)

- `app.js` defines `window.antoraSearch.initSearch`, loads the real `search-index.js`
  generated by `@antora/lunr-extension`, and runs the extension's exact→begins-with→
  contains query chain. Results are grouped by component/version and **navigate** on
  Enter/click.
- `footer-scripts.hbs` loads `lunr.js → app.js → search-index.js` in order and no longer
  pulls the extension's `search-ui.js` (which bound to a `#search-input` we removed).
- Verified: real indexed hits with correct URLs; selecting a result navigates.

---

## 3. Mobile navigation — now IMPLEMENTED (was desktop-only)

- Burger in the topbar (≤1024px) toggles an off-canvas drawer with a scrim; closes on
  scrim click, Escape, or link tap; body scroll locked while open.
- On phones (≤640px) the topbar search collapses to an icon and the trailing breadcrumb
  ellipsizes, to save width.
- The **Axoniq Platform** button and **theme toggle** moved from the topbar into the
  **drawer footer** (matches the original design intent; frees topbar space on mobile).
- Verified at 375px (open/close, scrim) and 1400px (persistent drawer).

## 4. Preview-only content removed
The temporary "Axoniq CLI" landing page (an uncommitted edit to
`axoniq-library-site` `content/home/.../index.adoc`) was a preview demo and has been
reverted to the real "AxonIQ Docs" landing. It is **not** part of the deliverable.
